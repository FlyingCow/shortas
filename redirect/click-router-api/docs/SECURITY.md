# Security Implementation Guide

This document outlines the comprehensive security layer implemented in the Click Router API with JWT authentication via Keycloak.

## Security Features Implemented

### 1. Authentication & Authorization

#### JWT Authentication
- **JWT Token Validation**: Real-time validation with Keycloak JWKS
- **Token Introspection**: RPT token support for fine-grained authorization
- **Keycloak Integration**: Centralized identity and access management
- **Permission System**: Role-based and scope-based permissions

#### Supported Authentication Methods
```http
# JWT Bearer Token Authentication
Authorization: Bearer eyJhbGciOiJSUzI1NiIsInR5cCI6IkpXVCJ9...

# RPT Token for Fine-grained Authorization
Authorization: Bearer rpt_token_for_uma_authorization
```

#### Permission System
```rust
// JWT Claims Structure
{
  "sub": "user_id",
  "realm_access": {
    "roles": ["user", "admin", "readonly"]
  },
  "resource_access": {
    "click-router-api": {
      "roles": ["read:routes", "write:routes", "read:certificates"]
    }
  },
  "scope": "openid profile email"
}

// Available Roles and Scopes
"read:routes"      // Read route information
"write:routes"     // Create/update routes
"delete:routes"    // Delete routes
"read:certificates" // Read certificate information
"write:certificates" // Create/update certificates
"delete:certificates" // Delete certificates
"read:user_settings" // Read user settings
"write:user_settings" // Update user settings
"admin"           // Administrative access
"uma_protection"  // UMA resource protection
```

### 2. Rate Limiting

#### Implementation
- **In-memory rate limiting** with configurable windows
- **Per-client identification** using IP + User-Agent
- **Default limits**: 100 requests per minute
- **Configurable per user/client**

#### Rate Limit Headers
```http
X-RateLimit-Limit: 100
X-RateLimit-Remaining: 95
X-RateLimit-Reset: 1640995200
```

### 3. Input Validation

#### Request Validation
- **Parameter length limits** (1000 characters max)
- **Injection attack prevention** (SQL, NoSQL, XSS)
- **Content length limits** (1MB max)
- **Malicious character detection**

#### Validation Rules
```rust
// Path parameters
- Max length: 1000 characters
- Forbidden: ', ", ;, <, >, &
- URL encoding required for special characters

// Request body
- Max size: 1MB
- JSON format validation
- Required field validation
```

### 4. Security Headers

#### Implemented Headers
```http

X-XSS-Protection: 1; mode=block
Strict-Transport-Security: max-age=31536000; includeSubDomains

```

### 5. JWT Token Management

#### Token Lifecycle
1. **Issuance**: Generated by Keycloak authentication server
2. **Validation**: Real-time JWT signature verification with JWKS
3. **Introspection**: RPT token validation for fine-grained authorization
4. **Expiration**: Time-based expiration with configurable clock skew
5. **Refresh**: Token refresh support via Keycloak
6. **Revocation**: Token revocation through Keycloak

#### JWT Configuration
```rust
// JWT Configuration
pub struct JwtConfig {
    pub keycloak_base_url: String,     // Keycloak server URL
    pub realm: String,                 // Keycloak realm
    pub client_id: String,             // OAuth client ID
    pub client_secret: Option<String>, // OAuth client secret
    pub audience: Option<String>,       // Token audience
    pub issuer: String,                // Token issuer
    pub jwks_endpoint: String,         // JWKS endpoint
    pub introspection_endpoint: String, // Token introspection endpoint
}
```

### 6. Route Protection

#### Public Endpoints
- `/public/health` - Health check
- `/public/metrics` - Basic metrics
- `/api-doc/*` - API documentation
- `/swagger-ui/*` - Swagger UI

#### Protected Endpoints (JWT Authentication Required)
- `/v1/routes/*` - Route management
- `/v1/certificates/*` - Certificate management
- `/v1/user-settings/*` - User settings

#### RPT Endpoints (Fine-grained Authorization)
- `/rpt/routes/*` - Route management with UMA authorization
- `/rpt/certificates/*` - Certificate management with UMA authorization
- `/rpt/user-settings/*` - User settings with UMA authorization

## Security Middleware Stack

### Middleware Order
1. **Security Headers** - Add security headers
2. **Rate Limiting** - Check rate limits
3. **Input Validation** - Validate requests
4. **JWT Authentication** - Verify JWT tokens
5. **JWT Authorization** - Check roles and permissions

### Implementation
```rust
// JWT Protected Routes
let protected_routes = Router::with_path("/v1")
    .hoop(security_headers_middleware)    // 1. Security headers
    .hoop(rate_limit_middleware)         // 2. Rate limiting
    .hoop(validation_middleware)          // 3. Input validation
    .hoop(jwt_auth_middleware)            // 4. JWT Authentication
    .hoop(jwt_authorization_middleware)    // 5. JWT Authorization
    .push(api_routes());

// RPT Protected Routes (Fine-grained Authorization)
let rpt_routes = Router::with_path("/rpt")
    .hoop(security_headers_middleware)    // 1. Security headers
    .hoop(rate_limit_middleware)         // 2. Rate limiting
    .hoop(validation_middleware)          // 3. Input validation
    .hoop(rpt_auth_middleware)            // 4. RPT Authentication
    .hoop(jwt_authorization_middleware)   // 5. JWT Authorization
    .push(api_routes());
```

## Error Handling

### Security Error Responses
```json
{
  "status_code": 401,
  "error": "Authentication error: InvalidApiKey",
  "details": "JWT token is invalid or expired"
}
```

### Error Types
- **401 Unauthorized**: Invalid/missing JWT token, expired token, invalid signature
- **403 Forbidden**: Insufficient permissions, missing roles/scopes
- **429 Too Many Requests**: Rate limit exceeded
- **400 Bad Request**: Invalid input/validation errors
- **502 Bad Gateway**: Keycloak server unavailable, JWKS fetch failed

## Configuration

### Environment Variables
```bash
# JWT Configuration
KEYCLOAK_BASE_URL=http://keycloak:8080  # Keycloak server URL
KEYCLOAK_REALM=master                   # Keycloak realm
KEYCLOAK_CLIENT_ID=click-router-api # OAuth client ID
KEYCLOAK_CLIENT_SECRET=secret           # OAuth client secret (optional)
KEYCLOAK_AUDIENCE=click-router-api  # Token audience (optional)

# JWT Validation Settings
JWT_VALIDATE_ISSUER=true                # Validate token issuer
JWT_VALIDATE_AUDIENCE=true              # Validate token audience
JWT_VALIDATE_EXPIRATION=true            # Validate token expiration
JWT_CLOCK_SKEW_SECONDS=60               # Clock skew tolerance

# RPT Configuration
RPT_ENABLED=false                       # Enable RPT token support
RPT_INTROSPECTION_TIMEOUT=10            # Introspection timeout (seconds)
RPT_CACHE_TTL=300                       # Token cache TTL (seconds)

# Security settings
SECURITY_RATE_LIMIT=100                 # Requests per minute
SECURITY_MAX_BODY_SIZE=1048576          # Max request body size (1MB)
SECURITY_ENABLE_HTTPS=true              # Force HTTPS
```

## Best Practices

### 1. JWT Token Security
- **Never log JWT tokens** in plain text
- **Use HTTPS only** for token transmission
- **Implement token refresh** for long-lived sessions
- **Monitor token usage** for anomalies
- **Validate token signatures** with JWKS
- **Handle token expiration** gracefully

### 2. Rate Limiting
- **Set appropriate limits** based on use case
- **Implement progressive backoff** for repeated violations
- **Monitor rate limit violations** for abuse detection

### 3. Input Validation
- **Validate all inputs** at the boundary
- **Use allowlists** instead of blocklists
- **Implement proper encoding** for special characters
- **Log validation failures** for monitoring

### 4. Error Handling
- **Don't leak sensitive information** in error messages
- **Use consistent error formats** across all endpoints
- **Log security events** for audit trails
- **Implement proper HTTP status codes**

## JWT Security Considerations

### Token Security
- **Token Storage**: Never store JWT tokens in localStorage (use httpOnly cookies)
- **Token Transmission**: Always use HTTPS for token transmission
- **Token Expiration**: Implement short-lived access tokens with refresh tokens
- **Token Revocation**: Use Keycloak's token revocation for immediate invalidation
- **Token Rotation**: Implement token rotation for enhanced security

### Keycloak Integration
- **JWKS Caching**: Cache JWKS keys to reduce Keycloak load
- **Connection Pooling**: Use connection pooling for Keycloak requests
- **Failover Handling**: Implement fallback mechanisms for Keycloak unavailability
- **Health Checks**: Monitor Keycloak server health and availability

### RPT Token Security
- **Token Introspection**: Validate RPT tokens through Keycloak introspection
- **Permission Scopes**: Implement fine-grained permission checking
- **UMA Compliance**: Follow UMA 2.0 specifications for resource protection
- **Token Caching**: Cache introspection results to improve performance
